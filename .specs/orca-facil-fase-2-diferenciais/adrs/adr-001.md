# ADR-001: Modelo de interação do cliente no link de aprovação — Aprovação simples

## Status

Aceito

## Data

2026-07-25

## Contexto

O link de aprovação digital é o diferencial central da Fase 2. A decisão-chave é qual nível de interatividade o cliente tem ao acessar o link: apenas confirmar que aprova, deixar uma mensagem de ajuste, ou selecionar entre versões do orçamento antes de aprovar. O modelo escolhido define a complexidade do fluxo, os estados do orçamento e o volume de trabalho de implementação.

## Decisão

Adotar **Aprovação simples**: o cliente acessa o link, visualiza o orçamento e pode clicar em "Aprovar" ou "Tenho dúvidas". "Tenho dúvidas" abre o WhatsApp do marceneiro com mensagem pré-preenchida. Não há entrada de texto no link, não há seleção de versão. Quando o cliente clica em "Aprovar", o status do orçamento muda para "aprovado" e o marceneiro é notificado.

## Alternativas Consideradas

### Alternativa 1: Aprovação com campo de ajuste

- **Descrição**: Terceiro botão "Preciso de ajustes" que abre campo de texto livre para o cliente deixar uma mensagem antes de rejeitar.
- **Prós**: Captura o motivo de não aprovação sem o cliente sair do link; elimina o "sumiu no WhatsApp sem explicar".
- **Contras**: Adiciona um novo estado de notificação (mensagem de ajuste vs. aprovação), mais fluxos de e-mail, mais complexidade no gerenciamento de estados do orçamento.
- **Por que rejeitada**: O WhatsApp já existe como canal de dúvidas e é onde o marceneiro opera naturalmente. Duplicar esse canal no link adiciona complexidade sem remover atrito real — o cliente que quer ajuste já abre o WhatsApp.

### Alternativa 2: Link com seleção de versão

- **Descrição**: Quando o orçamento tem múltiplas versões (padrão vs. premium), o cliente escolhe qual prefere diretamente no link antes de aprovar.
- **Prós**: Fecha a negociação de versões sem nova conversa; marceneiro recebe qual versão foi aprovada.
- **Contras**: Agrega valor apenas em orçamentos com múltiplas versões (minoria dos casos); adiciona estado de seleção e lógica de versão ao fluxo público; mais complexo para uma primeira versão pública.
- **Por que rejeitada**: A comparação de versões já aparece na página do link (exibição informativa). A decisão de qual versão o cliente quer ainda acontece naturalmente na conversa com o marceneiro — o link de aprovação é usado depois que a decisão já foi tomada.

## Consequências

### Positivas

- Implementação mais rápida e menor superfície de bugs na rota pública.
- Fluxo de estados simples: o orçamento só tem dois destinos via link (aprovado ou sem resposta).
- Zero atrito para o cliente — uma ação, um clique.
- A página permanece focada em exibir o orçamento, não em coletar input.

### Negativas

- Não captura motivos de não aprovação diretamente no produto; o marceneiro depende do WhatsApp para entender rejeições.

### Riscos

- Se a taxa de abertura do link for alta mas a taxa de aprovação for baixa, o produto não tem dados estruturados para diagnosticar o problema. Mitigação: o dashboard de conversão (Fase 2) mostra a taxa de aprovação; o marceneiro pode identificar o padrão e ajustar seus orçamentos.

## Notas de Implementação

A página pública `/o/[token]` não requer autenticação. O token (UUIDv4) é gerado quando o orçamento muda para status "enviado". O link expira na data de validade do orçamento ou quando o status muda para "cancelado".
