# ADR-005: Dados de fallback do catálogo regional como JSON estático no código

## Status

Aceito

## Data

2026-07-25

## Contexto

O catálogo pré-preenchido regional exige dados de referência de preços de materiais e serviços de marcenaria por estado. A fonte externa definitiva ainda não está definida (questão em aberto no PRD). É necessário uma estratégia de fallback confiável para o lançamento.

## Decisão

Implementar o fallback como **JSON estático em `lib/catalog/regional-defaults.ts`**: um array de itens de catálogo agrupados por UF, hardcoded no código. O endpoint `GET /api/catalog/regional-suggestions?state=[UF]` tenta a fonte externa primeiro e, em caso de falha ou ausência de configuração, retorna os dados do JSON estático. Dados atualizados via deploy (sem migração de banco).

## Alternativas Consideradas

### Alternativa 1: Tabela no banco (system_regional_catalog)

- **Descrição**: Nova tabela `system_regional_catalog(uf, name, type, unit, unit_price)` com RLS de leitura pública (anon). Populada via seed. Atualizável sem deploy.
- **Prós**: Dados editáveis pelo admin sem deploy; pode ser atualizado via painel admin no futuro.
- **Contras**: Nova tabela + migração + seed + política RLS; acoplamento de dados de fallback ao banco de produção; overhead de conexão para dado que muda raramente.
- **Por que rejeitada**: Os dados regionais de fallback são estáveis (MDF, ferragens, mão de obra não mudam preço semana a semana). Um deploy por atualização de preços é aceitável até que o volume de usuários justifique a infraestrutura de admin de dados.

## Consequências

### Positivas

- Zero tabela nova, zero migração, zero política RLS adicional.
- Dados de fallback testáveis com imports diretos (sem banco mock).
- Versionados junto com o código — changelog automático via git.

### Negativas

- Atualizar preços exige um deploy.
- Sem interface admin para edição — o desenvolvedor deve manter o arquivo manualmente.

### Riscos

- Dados de fallback ficarem desatualizados se o produto crescer sem processo de revisão. Mitigação: comentário no arquivo com data da última revisão e lembrete no PRD de Fase 2C para implementar fonte externa antes de 100 usuários ativos.
