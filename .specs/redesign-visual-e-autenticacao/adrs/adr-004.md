# ADR-004: Layout Responsivo com Sidebar + Bottom Nav no Mesmo Arquivo

## Status

Aceito

## Data

2026-07-22

## Contexto

O produto precisa de dois layouts distintos por breakpoint: bottom nav fixo em mobile (< 1024px) e sidebar fixa em desktop (≥ 1024px). O layout autenticado atual (`app/(app)/layout.tsx`) é um Server Component que já centraliza proteção de rota e carregamento de dados de subscription.

## Decisão

Implementar os dois layouts no único `app/(app)/layout.tsx` existente usando classes Tailwind responsivas:

- `<Sidebar>` renderizado com `hidden lg:flex` — invisível em mobile, visível em desktop
- `<BottomNav>` renderizado com `lg:hidden` — visível em mobile, oculto em desktop
- `<main>` com `lg:ml-64` para compensar a largura da sidebar em desktop

```tsx
<div className="flex min-h-screen">
  <Sidebar className="hidden lg:flex" />
  <div className="flex flex-col flex-1 min-w-0">
    {showTrialBanner && <TrialBanner daysLeft={daysLeft} />}
    <main className="flex-1 pb-16 lg:pb-0">{children}</main>
    <BottomNav className="lg:hidden" />
  </div>
</div>
```

## Alternativas Consideradas

### Alternativa 1: Dois grupos de rotas separados — (app-mobile) e (app-desktop)

- **Descrição**: Layouts distintos em route groups separados.
- **Prós**: Controle independente por viewport; sem CSS condicional.
- **Contras**: Duplica a lógica de proteção de rota e carregamento de subscription; maior manutenção.
- **Por que rejeitada**: Duplicação desnecessária — o conteúdo das páginas é idêntico; apenas o chrome muda.

### Alternativa 2: Detecção de viewport via JavaScript (useMediaQuery)

- **Descrição**: Client Component detecta viewport e renderiza sidebar ou bottom nav condicionalmente.
- **Prós**: Lógica explícita.
- **Contras**: Flash de layout incorreto no SSR; layout.tsx é Server Component — exigiria extrair para Client Component.
- **Por que rejeitada**: CSS responsivo resolve sem custo de hidratação ou flash.

## Consequências

### Positivas

- Zero duplicação de lógica de auth e subscription.
- CSS responsivo é zero-JS — sem flash de layout no SSR.
- Sidebar e BottomNav são componentes independentes e testáveis.

### Negativas

- `app/(app)/layout.tsx` cresce com dois componentes de navegação — requer atenção à legibilidade.

### Riscos

- Padding/margin entre `main` e sidebar pode causar overflow em viewports intermediárias (1024px–1280px). **Mitigação**: testar em 1024px e 1280px antes de marcar como concluído.
