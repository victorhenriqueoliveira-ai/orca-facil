# ADR-003: Tokens de Design via @theme em globals.css (Tailwind v4)

## Status

Aceito

## Data

2026-07-22

## Contexto

O projeto usa Tailwind v4 com `@theme inline` em `globals.css` — sem `tailwind.config.ts`. A paleta atual (`blue-600`, `gray-*`) está hardcoded nas classes de cada componente. A nova identidade visual exige tokens semânticos (`brand-primary`, `brand-support`, etc.) reutilizáveis em toda a base de código.

## Decisão

Definir todos os tokens de cor e fonte da nova identidade visual em um único bloco `@theme` dentro de `globals.css`, seguindo o padrão já adotado pelo projeto:

```css
@theme {
  --color-brand-primary: #C2703A;
  --color-brand-support: #2D5D5A;
  --color-bg-base: #FAF7F2;
  --color-text-base: #2B2621;
  --color-border: #E5DDD3;
  --color-success: #4A7C59;
  --color-warning: #D4A017;
  --color-error: #B3403A;
  --font-sans: var(--font-manrope);
}
```

Isso habilita classes Tailwind como `bg-brand-primary`, `text-brand-support`, `border-border` em qualquer componente sem configuração adicional.

## Alternativas Consideradas

### Alternativa 1: Arquivo separado design-tokens.css importado em globals.css

- **Descrição**: Tokens em arquivo dedicado, importado via `@import`.
- **Prós**: Separação de responsabilidades; tokens isolados facilitam auditoria.
- **Contras**: Adiciona indireção sem benefício real em projeto pequeno; padrão diferente do que o projeto já usa.
- **Por que rejeitada**: Fuga do padrão Tailwind v4 já estabelecido no projeto.

### Alternativa 2: Classes hardcoded por componente (sem tokens globais)

- **Descrição**: Usar `bg-[#C2703A]` diretamente nas classes.
- **Prós**: Zero setup.
- **Contras**: Manutenção impossível — qualquer mudança de cor exige busca global; sem semântica.
- **Por que rejeitada**: Anti-padrão para qualquer projeto com design system.

## Consequências

### Positivas

- Tokens disponíveis como classes Tailwind em qualquer arquivo — sem import adicional.
- Mudança de paleta futura requer editar apenas o bloco `@theme`.
- Alinhado com o padrão Tailwind v4 do projeto.

### Negativas

- `globals.css` cresce — deve ser documentado para que novos desenvolvedores entendam o bloco `@theme`.

### Riscos

- Colisão de nome com tokens Tailwind defaults (ex.: `--color-background` já é usado). **Mitigação**: usar prefixo `brand-` para cores de identidade e `bg-base` / `text-base` para neutros, evitando sobrescrever os defaults do Tailwind.
